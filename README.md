## Cactus

A Hugo theme for personal blogs, maintained in [OmeletWithoutEgg/hugo-theme-cactus](https://github.com/OmeletWithoutEgg/hugo-theme-cactus).

This is a fork of [monkeyWzr/hugo-theme-cactus](https://github.com/monkeyWzr/hugo-theme-cactus), originally ported from the Hexo theme [Cactus](https://github.com/probberechts/hexo-theme-cactus) by @probberechts.

[Live demo](https://omeletwithoutegg.github.io/hugo-theme-cactus/).

Some works are still in progress. See [TODOS](#todos) below.

## Template structure

This fork uses the [Hugo v0.146.0+ template system](https://gohugo.io/templates/new-templatesystem-overview/).
Hugo Extended and Dart Sass are required; the current site is tested with Hugo 0.168.0.

- `layouts/baseof.html`: shared shell for the home page, lists, and regular pages.
- `layouts/home.html`: home page.
- `layouts/page.html`: regular pages such as About.
- `layouts/posts/page.html`: article layout with post navigation and metadata.
- `layouts/list.html`: section archives and individual taxonomy term listings.
- `layouts/taxonomy.html`: tag and category overview pages.
- `layouts/_partials/`: reusable fragments and optional head/body hooks.
- `layouts/_markup/`: Markdown render hooks.

Site overrides must use the same paths (for example, `layouts/_partials/optional-body.html`).
A site-specific search page can use `layouts/search.html`, with its JSON index in `layouts/home.json`.
The public search index URL remains `/index.json`.

## Naming conventions

Custom template and stylesheet filenames, HTML classes/IDs, and Scratch keys use
kebab-case (for example, `page-nav.html`, `actions-desktop.scss`, and `post-title`).
Local template and JavaScript variables use camelCase. Hugo/Sass special names and
external identifiers retain their required spelling.

Site overrides should use `page-nav.html` / `page-nav-mobile.html` and
`comments/cactus-comments.html`. Custom CSS targeting the old `posttitle`,
`postdate`, or `tagcloud` classes should use `post-title`, `post-date`, or `tag-cloud`.
The existing `cactus_comments` comment-engine setting is unchanged.

## Theme development and demo

The theme follows the structure generated by `hugo new theme`: sample pages live
in `content/`, the demo configuration is `hugo.toml`, and templates live in `layouts/`.
The sample projects list is in `data/projects.json`.
Explicit module mounts export only theme components when Cactus is used by another
site, so the demo content and project data are not added to that site.

With Hugo and Dart Sass installed, run these commands from the theme root:

```sh
hugo server --buildDrafts
hugo --minify
```

Build output and caches (`public/`, `resources/`, `.hugo_build.lock`) are ignored.
The demo is tested with Hugo 0.168.0. Its `locale` setting requires Hugo 0.158.0 or later.
Comments and analytics are disabled until configured. The four sample posts cover
multilingual Markdown typography, code blocks, MathJax, and bilingual public-domain
lyrics. Goldmark passthrough preserves TeX
notation; only the mathematics post enables MathJax.

### Deploy the demo to GitHub Pages

In the theme repository, set **Settings → Pages → Build and deployment → Source**
to **GitHub Actions**. The [workflow](.github/workflows/gh-pages.yml) builds pull
requests and deploys pushes to the default branch (`master` or `main`). You can
also run it manually on the default branch.

The workflow builds from the theme root and uses the Pages URL as Hugo's base URL.
The demo URL is https://omeletwithoutegg.github.io/hugo-theme-cactus/ unless a custom
domain is configured. It publishes a Pages artifact without committing generated
files to a `gh-pages` branch.

## Install

1. clone cactus to your hugo site's `themes` folder.
```
git clone https://github.com/OmeletWithoutEgg/hugo-theme-cactus.git themes/cactus
```

2. change your theme to cactus in your site config
```toml
# hugo.toml

theme = "cactus"
```

3. config your site. See [Config] or a [complete config sample](hugo.toml)
4. test your site
```
hugo server
```

5. publish your site in your prefered way. See hugo's doc: [Hosting & Deployment](https://gohugo.io/hosting-and-deployment/)

See [Theme development and demo](#theme-development-and-demo) to preview the theme.

## Config

### Color themes

```toml
[params]

  colortheme = "white" # dark, light, white, or classic
```

### Custom CSS

Place stylesheets in your site's `assets/` directory and list their paths:

```toml
[params]
  css = ["css/custom.css"]
```

The compiled theme CSS comes first, followed by these files in the configured
order. Hugo combines them into one stylesheet, then minifies and fingerprints it
in production. Paths must resolve to assets, not `static/` files or external URLs.
CSS `url()` paths are relative to the generated stylesheet in `css/`.

### Custom head and body content

Create these files in your **site's** `layouts/_partials/` to override the empty
hooks provided by the theme. Both receive the current page as `.`.

- `optional-head.html`: add stylesheets or metadata inside `<head>`, after the theme CSS.
- `optional-body.html`: add scripts or custom HTML before `</body>`.

For `assets/css/custom.css`, use this in `optional-head.html`:

```go-html-template
{{ partial "asset-style.html" (resources.Get "css/custom.css") }}
```

For `assets/js/custom.js`, use this in `optional-body.html`:

```go-html-template
{{ partial "asset-script.html" (dict "path" "js/custom.js") }}
```

These helpers minify and fingerprint assets in production. Prefer `params.css`
for stylesheets that should join the theme bundle; styles added through
`optional-head.html` are loaded separately. Do not include the same stylesheet
in both places.

### JavaScript and code copying

Theme JavaScript lives in `assets/js/` and is bundled with Hugo's `js.Build`.
Development builds include source maps; production builds minify and fingerprint
the bundles. No Node.js installation is needed to build the site.

The code block render hook marks pages containing fenced code blocks. Those pages
load the copy-button bundle, including the bundled ClipboardJS dependency. Copy
buttons support both table and inline line numbers without including the numbers
in the copied text. Site overrides are not required.

For a page containing only raw HTML or indented code blocks, set `copyCode: true`
in front matter to enable copying. Set `copyCode: false` to disable copying on a
page. If you override `layouts/_markup/render-codeblock.html`, retain its
`Page.Store` flag or use this front matter setting.

### Homepage settings

* description: description will be displayed in the homepage. Markdown syntax is supported in the description string.
```toml
[params]

  description = "Hugo is a general-purpose website framework. Technically speaking, Hugo is a static site generator. Unlike systems that dynamically build a page with each visitor request, Hugo builds pages when you create or update your content. Since websites are viewed far more often than they are edited, Hugo is designed to provide an optimal viewing experience for your website’s end users and an ideal writing experience for website authors."
```

* set your main section (used as the link for the "writings" title on the homepage)

```toml
[params]
  mainSection = "posts"
```

* change the default main section title from Writings, to something else:

```toml
[params]
  mainSectionTitle = "Blog"
```

* Show only the 5 most recent posts (default)

```toml
[params]
  showAllPostsOnHomePage = false
  postsOnHomePage = 5
```
* show all posts

```toml
[params]
  showAllPostsOnHomePage = true
  postsOnHomePage = 5 # this option will be ignored
```

* show tagsoverview (default) or not
* 
```toml
[params]
  tagsOverview = true
```

* display the table of contents inline on blog posts, rather than as part of the navigation menu:

```toml
[params]
  tocInline = true
```

* show projects list (default) or not.

```toml
[params]
  showProjectsList = true
  projectsUrl = "https://github.com/OmeletWithoutEgg/hugo-theme-cactus"
```

Projects section will not be shown if no data file is detected. See [Projects list](#projects-list) below.

### Projects list

Create your projects data file `data/projects.yaml|toml|json`. Hugo support yaml, toml and json formats.
for former hexo cactus users: please assign your json array to a `list` key.

for example, `data/projects.json`:
```json
{
   "list": [
      {
         "name":"Hexo",
         "url":"https://hexo.io/",
         "desc":"A fast, simple & powerful blog framework"
      },
      {
         "name":"Font Awesome",
         "url":"http://fontawesome.io/",
         "desc":"The iconic font and CSS toolkit"
      }
   ]
}
```

### Social media links

```toml
[[params.social]]
  name = "github"
  link = "https://github.com/OmeletWithoutEgg"

[[params.social]]
  name = "email"
  link = "you@example.com" # no need for "mailto:" at the start

[[params.social]]
  name = "linkedin"
  link = "https://www.linkedin.com/in/your-profile/"
```

The `name` key selects a bundled SVG in `assets/icons/`; `email`, `rss`, and `scholar` are also supported. Add custom icons to your site's `assets/icons/` directory. Missing icons fall back to a link icon with a build warning.

Bundled Font Awesome Free icons include their [license](assets/icons/LICENSE.txt).
The icon partial converts embedded attribution comments to SVG `<desc>` text so
attribution survives Hugo's default minification. No site-level `keepComments`
setting is required. Icons remain `aria-hidden` and the description is not displayed.

### Comments

Comments is disabled by default. Enable comments in your `.Site.Params`.
```toml
[params]
  [params.comments]
    enabled = true
    engine = "disqus" # also supports utterances and cactus_comments
```

You can also enable/disable comments per post. in your posts' front matter, add:
```yaml
comments: true
```

The site config is ignored when `comments` option exists in front matter.

The default engine is Disqus. Utterances and Cactus Comments are also supported; see the provider settings in [the example configuration](hugo.toml).

Before using disqus, you need to register and get your [disqus shortname](https://help.disqus.com/en/articles/1717111-what-s-a-shortname). Set `services.disqus.shortname` in your site configuration.

```toml
[services.disqus]
  shortname = "your-disqus-shortname"
```

### highlight

Use hugo's built-in [syntax highlighting](https://gohugo.io/getting-started/configuration-markup#highlight).

default config:

```toml
[markup]
  [markup.highlight]
    codeFences = true
    guessSyntax = false
    hl_Lines = ""
    lineNoStart = 1
    lineNos = false
    lineNumbersInTable = true
    noClasses = true
    style = "monokai"
    tabWidth = 4
```

### Analytics

Cactus uses Hugo's built-in Google Analytics template. Configure a Google Analytics 4 property in `hugo.toml`:

```toml
[services.googleAnalytics]
  id = "G-XXXXXXXXXX"
```

### RSS

The rss feed is not generated by default. you can enable it in your site config:

```toml
[params]
  rss = true
```

The rss link will be `https://example.com/index.xml` assuming your `baseURL` is set to `https://example.com/`

Please also check [Configure RSS](https://gohugo.io/templates/rss/#configure-rss)

### Mathjax

Cactus supports mathjax. Just add `mathjax` option in your site config:
```toml
[params]
  mathjax = true  # not required
```

You can also enable/disable mathjax per post. In your posts' front matter, add:
```yaml
mathjax: true # or false
```

The site config will be ignored when `mathjax` option exists in front matter.

### Archive 
Pagination on posts archive can be disabled to show all posts in chronological order

```toml
[params]
  showAllPostsArchive = true # or false (default)
```
